Mark already-coded interviews as fully coded

For interviews you coded before "Mark fully coded" existed. A mark tells training that every uncoded passage in the interview was judged as not belonging to the active scheme's themes, but only for themes that existed at the mark's date. Dating each mark to when you last coded that interview means themes you created later aren't covered by mistake. The real time of this action is recorded too.

Storage

Every training run stores a score for every segment, for every theme it trained, and those scores take up most of the database. Here you can delete the scores of old runs. A run's metrics, top terms, and settings are always kept, and so are your codes. Each theme's most recent runs and any pinned run are never deleted. Pin a run you cite or exported from: deleted scores can't be recreated exactly once your codes have changed.

Compact database

Deleting scores frees space inside the database file, but the file itself only shrinks after compacting. Compacting can take several minutes on a large database, needs free disk space of up to twice the database's size while it runs, and blocks coding and training until it finishes. If the project folder is synced (Dropbox, OneDrive…), the whole database will re-sync afterwards.
